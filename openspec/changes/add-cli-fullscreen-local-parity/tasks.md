# Ordered integration gates

- [ ] P0 record SHA/status/source hashes and initial executable baseline.
- [ ] P0 validate contracts, fixtures, coverage matrix and ownership.
- [ ] P1 generic fullscreen/mouse/Unicode/clipboard foundation (Sengoo owner).
- [ ] P1 implement centered monochrome TUI and shared command registry (UI owner).
- [ ] P1 connect real streaming/queued input and fresh approvals (core/root).
- [ ] P2 unified tool/event/policy contracts and continuously polled host (core).
- [ ] P2 managed-account adapters with verified EffectivePolicy (core/root).
- [ ] P2 model-aware compaction, multimodal/protocol continuation and retry (core).
- [ ] P3 checkpoint/branch/worktree/PTY/media/LSP/IDE (new child owners required).
- [ ] P4 hooks/plugins/Sengoo SDK/remote MCP/search/memory (child owners).
- [ ] P5 durable agents/teams/workflows/monitor/loop/background attach (child owners).
- [ ] P6 independent installation, desktop handoff and rollback acceptance (root).
- [ ] P6 reconcile capability matrix with artifacts and evidence before release.

Root owns main/command_line/state/session actions/scripts/docs/OpenSpec and final
integration. UI owns terminal/slash/commands/tui modules and their unit tests.
Core owns controller/executor/children/scheduler/agent/output/engine modules.
Foundation owner owns additive Sengoo terminal/IPC/Unicode and registrations.
Named checks must pass before a box is checked. A tested subset does not close
its entire phase, and fixtures do not qualify live services or clean machines.
