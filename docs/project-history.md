# 随项目保存聊天记录

在项目目录运行 `sen` 或 `sencode`，聊天记录保存在项目的
`.sencode/history.sqlite3`。文件保存稳定项目 ID、会话、消息、工具结果、
Plan/Goal 状态和累计用量；API 密钥仍在系统凭据库，不写入此文件。
会话选中的供应商、模型和思考强度也随历史保存，恢复时优先于全局默认值。
只改模型但没有再发送消息的选择同样保留；权限不会随模型偏好恢复。

退出并停止该项目的后台任务后，可以给项目根目录改名。进入新目录执行
`sen -c` 或 `sen resume` 即可继续原会话；`sen -r 搜索词` 搜索已有会话。
首次打开已有项目时，会自动收录共享数据库中属于该目录的历史。

共享数据库仍负责桌面接力与执行锁，本地文件随 CLI 的写事务更新。
共享库丢失时，先检查 `.sencode/history.sqlite3`，再使用 `sen --import-history -c` 明确导入；Goal 始终需要明确恢复。
工具结果未知、原目录仍存在的复制品、绑定另一个现存共享库等情况会明确
拒绝，不自动合并或重跑工具。移动前请关闭客户端，不要只复制正在写入的
SQLite 主文件而遗漏它的 WAL。

CLI 会在 `.sencode/.gitignore` 中追加历史文件和迁移锁的忽略规则，保留
已有内容。记录可能含私有代码和对话内容。
保留 `.sencode` 才能随目录带走历史；只保留一个空目录不能恢复记录。

本轮不迁移 API 配置、托管运行时内部会话、checkpoint 或后台进程。
桌面独立产生的新记录在下次 CLI 打开此项目时收录；桌面持续写入本地历史
及断电恢复仍需单独验证。运行目录就是当前项目范围，子目录启动不会隐式
改写成仓库根目录。两个 WAL 数据库的断电原子性不作保证。
