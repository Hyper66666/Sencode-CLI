# 中途补充消息与上下文压缩

任务执行期间输入消息，第一次 Enter 放入待发队列。输入框为空时再次按
Enter，将队列最前面的一条消息插入当前任务。Esc 仍可撤回尚在普通队列中的
最后一条消息；菜单、审批和多行编辑优先处理自己的按键。

插入不会取消正在进行的网络请求或工具。补充条件在当前响应或工具批次完成后、
下一次模型请求前生效；因此已经开始的操作不能靠插入消息撤销。需要立即停止
时仍使用取消。等待插入期间显示灰色 INSERTING，保存进会话后显示为用户消息。
插入沿用当前任务的模型、权限、Plan/Goal 和预算；不会重新运行已完成工具。

普通待发消息仍在当前任务结束后发送。若只想保留为下一轮消息，第一次 Enter
后继续编辑草稿或等待即可，不按第二次空 Enter。队列采用 FIFO 顺序。
斜杠命令保留到空闲后处理。受管理账号后端目前不能执行此插入协议，消息保留
在队列，不以取消重启来模拟。图片继续沿用现有能力检查与文件验证。

收到明确拒绝或任务结束前仍未插入时，消息返回暂停的队列。若宿主异常退出且
提交结果未确认，CLI 保留消息并明确提示检查历史，不自动重发。稳定消息 ID
随用户历史保存，丢失确认后重发相同 ID 也不能重复提交。

上下文摘要期间，活动标记统一为 Compacting，包括内部推理和重试阶段。
检查点保存成功后显示一行“上下文已压缩”，自动压缩随后继续原任务。
原来的英文压缩 NOTICE 已移除。真正的 NOTICE 标题和全部内容使用红色前景；
关闭颜色时保留普通文字。

JSONL schema v1 增补：原生 session 事件的 `live_steering`，控制命令 `steer`
（id、request_id、text、可选 images），以及 `steering_pending`、
`steering_applied`、`steering_rejected`、`context_compacted` 事件。
旧命令、旧事件封装和数据库结构保留。
